pnpm

发表于 2026-05-25 分类于 technical

大家都知道pnpm相比较npm、yarn，会更快，更省磁盘，那为什么会这样呢？

pnpm install 发什么了什么？

当我们执行以下pnpm install express之后，得到一个pnpm安装的express项目

相比较npm、yarn，pnpm安装的项目node_modules下面就只有package.json安装的包，且多了一个.pnpm的文件
.pnpm下面是项目所有需要用的包，包含嵌套依赖包。

第一步：全局store存储
当执行pnpm install express，pnpm会把express以及express的依赖包如accepts的文件下载到电脑的的全局仓库~/.pnpm-store
pnpm会把文件根据其内容哈希值命名，存放，全局唯一。

官方文档中给出了这么一张图，可以很清晰地明白其中的原理。

第二步：构建.pnpm 目录
pnpm会在node_modules/.pnpm中建立一个完全由版本号平铺的虚拟硬链接池
在这个池子里，目录的命名格式通常是 包名@版本号（或是加了依赖哈希）。
物理结构长这样：

问题来了.pnpm/里面实现平铺express如何找到accepts？
pnpm-test/node_modules/.pnpm/express@5.2.1/node_modules/ 内部：存在express/、accepts/、…文件夹
(1) express/文件夹里面的文件是通过硬链接从全局Store挂载过来的。
(2) 当express内部执行require(‘accepts’)时，就会在当前目录的node_modules下寻找。
(3) 于是，找到了pnpm-test/node_modules/.pnpm/express@5.2.1/node_modules/accepts/。
(4) 然而，这个accepts/不是真的文件夹，是一个软链接，它指向../../accepts@2.0.0/node_modules/accepts。
(5) 最终，express顺着软链接，成功读取到了它需要的 accepts 依赖。

第三步：映射项目依赖
项目中想要使用包也是在当前node_modules下面寻找
为了项目中能够import 'express',pnpm会在根目录下创建了一个软链接

所有的软链接连起来看，整个项目的物理布局是这样的

通过这种方式彻底解决幽灵依赖的问题。
