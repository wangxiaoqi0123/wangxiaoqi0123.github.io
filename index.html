pnpm

发表于 2026-05-25 分类于 technical

大家都知道pnpm相比较npm、yarn，会更快，更省磁盘，那为什么会这样呢？

pnpm install 发什么了什么？

当我们执行以下pnpm install express之后，得到一个pnpm安装的express项目

相比较npm、yarn，pnpm安装的项目node_modules下面就只有package.json安装的包，且多了一个.pnpm的文件
.pnpm下面是项目所有需要用的包，包含嵌套依赖包。

第一步：全局store存储
当执行pnpm install express，pnpm会把express以及express的依赖包如accepts的文件下载到电脑的的全局仓库~/.pnpm-store
pnpm会把文件根据其内容哈希值命名，存放，全局唯一。

官方文档中给出了这么一张图，可以很清晰地明白其中的原理。

第二步：构建.pnpm 目录
pnpm会在node_modules/.pnpm中建立一个完全由版本号平铺的虚拟硬链接池
在这个池子里，目录的命名格式通常是 包名@版本号（或是加了依赖哈希）。
物理结构长这样：

问题来了.pnpm/里面实现平铺express如何找到accepts？
pnpm-test/node_modules/.pnpm/express@5.2.1/node_modules/ 内部：存在express/、accepts/、…文件夹
(1) express/文件夹里面的文件是通过硬链接从全局Store挂载过来的。
(2) 当express内部执行require(‘accepts’)时，就会在当前目录的node_modules下寻找。
(3) 于是，找到了pnpm-test/node_modules/.pnpm/express@5.2.1/node_modules/accepts/。
(4) 然而，这个accepts/不是真的文件夹，是一个软链接，它指向../../accepts@2.0.0/node_modules/accepts。
(5) 最终，express顺着软链接，成功读取到了它需要的 accepts 依赖。

第三步：映射项目依赖
项目中想要使用包也是在当前node_modules下面寻找
为了项目中能够import 'express',pnpm会在根目录下创建了一个软链接

所有的软链接连起来看，整个项目的物理布局是这样的

通过这种方式彻底解决幽灵依赖的问题。

什么是Agent

大模型可以看做是一个大脑，很擅长回答问题。但无法感知或者改变外界环境。
为了解决这个问题我们可以给大模型接上对应的工具，比如 读写文件内容工具、查看文件列表工具、运行终端命令工具
有了这些工具大模型就相当于有了感官和四肢就可以自己操作文件，
那像这样把一个大模型和一堆工具组装起来，变成一个能感知和改变外界环境的智能程序，就称它为Agent

Agent运行模式

ReAct模式（Reasoning and Acting）



Plan-And-Execute模式
需要提供 生成计划的模型（Plan模型）以及动态调整计划的模型（Re-Plan模型）可以是同一个模型

RAG

发表于 2026-04-10 分类于 AI

为什么要使用RAG

是为了让大模型能够使用外部知识的技术。它的核心思想非常简单：先检索资料，再让大模型生成答案。

RAG的整体流程

RAG的实现可以大致分成两个阶段分别是数据准备阶段、用户问答阶段

数据准备阶段

主要用于将原始数据存入数据库
核心要点是 数据的切分原则

用户问答阶段

用户提出问题后，把问题向量化，然后根据向量数据库查找n条相似度最高的文本片段（召回），然后把这n条片段给到处理文本相似度的AI（CrossEncoder），再找到最精准的m条数据，然后跟用户问题一起给到大模型，大模型完成回答。

大模型的基本理解

发表于 2026-04-09 更新于 2026-04-11 分类于 AI

什么是大模型

大模型本质上就是一个通过大量数据训练出来的概率预测机器，核心目的用一句话来说就是：根据已有的内容，预测下一个最可能出现的词（Token）。

举个例子：假设给你一句话

今天天气很好，我想去___

脑袋就会联想：公园、散步、玩、其他

大模型就是把这种“经验”放大到几十亿句子的级别。

大模型是怎么工作的

我给发了一个消息给大模型到大模型回答我，这中间发生了什么？

第一步就是把用户发送的消息给拆分成Token
那什么是Token如何拆分呢？
有一套算法比如（BPE）来处理，简单来说就是，是先把所有文字序列化为Token，然后再根据模型训练的资料，匹配出最高频出现在一起的字的组合成新的Token。
所以Token可以是单个的字，也能是词语…

Token生成好之后就会把Token转化成向量

然后丢给大模型

大模型一顿运算，就配出一个个概率最高的向量

然后再由映射出文本给到用户

mysql 事务

发表于 2025-02-07 分类于 mysql

手动提交事务

通过 set autocommit = 0 | false; 关闭事务自动提交，然后手动执行 commit 或者 rollback。
语法：

注意：
关闭自动提交后，直到执行 COMMIT 或 ROLLBACK 前，所有的 SQL 语句都会被视为一个事务的一部分。
commit 提交事务，将所有更改永久保存到数据库中。
rollback 回滚事务，撤销自上次 commit 或 rollback 后执行的所有更改。
设置 set autocommit = 1 | true; 可以重新开启自动提交。
通过 set autocommit 设置事务的提交方式，只适用于当前会话。
通过 show variables like ‘autocommit’; 可以查看当前会话的自动提交状态。

开启独立事务

通过 start transaction; 开启一个独立的事务，然后执行一系列的 SQL 语句，最后通过 COMMIT 或 ROLLBACK 来提交或回滚事务。
语法：

注意：
不管是否关闭自动提交，都可以通过 start transaction 开启一个独立的事务。

事务特性

事务不支持 DDL 语句（如 CREATE TABLE、ALTER TABLE 等），因为这些操作会立即生效，无法回滚。

事务隔离

隔离作用：
避免并发事务之间的干扰，保证数据的一致性。
隔离级别：
read-uncommitted（读未提交）：最低的隔离级别，会出现 脏读 不可能重复读 幻读。
read-committed（读已提交）：避免了脏读，可能出现 不可重复读 和幻读。
repeatable-read（可重复读）：避免了脏读和不可重复读，可能出现幻读。
serializable（可串行化）：最高的隔离级别，避免了脏读、不可重复读和幻读。
隔离问题：
脏读：一个事务读取了另一个未提交的事务的数据（真实错误）。
不可重复读：一个事物读取了另一个事务提交的修改数据（不符合一致性原则，不是数据错误）。
幻读：一个事务读取了另一个事务提交的插入数据（不符合一致性原则，不是数据错误）。
修改查看语法：
select @@transaction_isolation;
set transaction_isolation = 隔离级别;
总结：
隔离级别越高，数据越安全，性能越低。建议设置隔离级别为 read-committed。

表关系

一对一
特点：双方的数据行都对应对方至多一条数据
意义：用于优化冷热数据查询
如何建立关系：
方式一：子表的外键与主键融合，两张表公用同一个主键。
方式二：子表外键添加唯一约束

一对多
特点：主表对应多条子表数据，子表对应主表至多一条数据
意义：解决数据冗余问题。
如何建立关系：
子表的外键不进行约束。

多对多
特点：双方的数据行都可以对应对方多条数据
如何建立关系：
多对多需要创建中间表建立数据之间的关联。
中间表包含两个外键，主表数据之间间接关联。

多表查询

内连接（inner join）
语法：

作用：
可以将多个表的数据行，正确水平拼接到一个结果集中。
两个表中必须存在相同的主外键，内连接才能查询到结果。

存在N个表相连接时，会先将前两个表进行连接，再将结果与第三个表进行连接。

嵌套子查询

概念：一个sql语句中嵌套了另一个或多个完整的sql语句，称为子查询或内查询。

根据子查询的结果，可分为4种情况：
标量子查询：子查询返回结果是一行一列，单一值，一般用在条件判断。
行子子查询：子查询返回结果是一行多列，一般用于插入数据的值，或者整体对比。
列子子查询：子查询返回结果是一列多行，一般用于条件对比，需要配合 in any all 等关键字。
表子子查询：子查询返回结果是多行多列，不能用于条件判断，一般用于查询的虚拟表的中间表。

提示：
any all 关键字只用在列子查询中。
any 关键字相当于 or 关系，all 关键字相当于 and 关系。

子查询可以在select，update，delete，insert，等语句中使用。
注意：update，delete 中使用时，更新的表与子查询的表是同一个表，会产生冲突。

mysql 约束

发表于 2025-02-06 分类于 mysql

NOT NULL

作用：确保列中不能有NULL值。

DEFAULT

作用：为列提供一个默认值。

提示：如果主动插入NULL值，则不会触发默认值行为。

CKECK

作用：确保列中的值满足某个条件。

AUTO_INCREMENT

作用：自动增长约束，确保列中的数据唯一且不为空。

提示：
添加AUTO_INCREMENT约束的列必须是主键或者唯一约束。
每个表只能有一个AUTO_INCREMENT约束。
自增列必须是整数类型。
插入数据时，不指定自增列的值或值为null或0时，会自动增长。

PIRMARY KEY

作用：主键约束，确保列中的数据唯一且不为空。

提示：一个表只能有一个主键，但是可以有多个字段组合成一个复合主键。

UNIQUE

作用：唯一约束，确保列中的数据唯一。

提示：同一个表上可以多个字段有唯一约束，或者多个字段组合唯一。

FOREIGN KEY

作用：外键约束，确保列中的数据在另一个表中存在。

外键概念：外键就是在一个表中定义另一个表的主键列，从而达到两个表之间的关联。
外键约束概念：外键约束是用来保证外键数据正确的限制。外键没有外键约束也是外键，最好添加外键约束。
级联配置：
在定义外键时，可以使用ON DELETE 配置 ON UPDATE 配置 关键字来指定当父表数据被删除或更新时，子表应该执行的操作。
CASCADE 级联删除/更新，如果删除/更新父表的记录，子表对应记录也被删除/更新。
SET NULL 子表的外键允许为空，且删除父表记录时，子表数据应保留但失去关联，如部门被删除时，员工仍然存在，但 department_id 变 NULL。
RESTRICT / NO ACTION（默认）限制删除/更新父表记录，如果子表有对应数据则不允许操作。

注意：
一个表可以有多个外键约束。
外键是跨表引用其他表的主键值。
外键所在的表叫子表，被引用的主键所在的表叫主表。
外键的类型必须必须和主键的类型相同，命名最好相同。
主外键关系，就代表两张表存在关联关系，之后可以进行多表的水平查询。
有主外键约束，删除主表数据的前提是子表没有引用数据！否则应该先删除子表的引用数据，再删除主表数据！

补充

注意：
使用ALTER TABLE 表名 MODIFY 字段 数据类型;进行修改时，会将之前的 NOT NULL、DEFAULT、AUTO_INCREMENT约束一并移除。
